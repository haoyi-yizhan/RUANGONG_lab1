# 实验二 UI 与实验三实现对照

实验三沿用 `lab2/交付物/UI界面/界面1.png` 至 `界面10.png` 的视觉与页面结构。应用名统一为“校园票务”；页面底色 #EEF2F7，主文字 #334155，辅助文字 #6B7A8C / #8A97A6，重点控件 #7C8AA0，微软雅黑，主按钮至少 44px。

| 原型 | 运行界面对应 |
|---|---|
| 1 登录注册 | 白色顶栏、居中登录/注册卡片，底部四类角色权限说明；恢复码找回密码 |
| 2 实名认证 | 登录未实名后进入实名卡，姓名与身份证号绑定，认证后可购票 |
| 3 演出列表 | 顶部搜索与筛选，桌面三列演出卡片；主题、地点、主讲、时间及仅余票筛选 |
| 4 演出详情 | 左侧横幅与演出介绍、须知，右侧购退规则与单选票档，合计与提交订单 |
| 5 支付出票 | 左侧订单摘要、实时支付倒计时及模拟支付，右侧出票结果、座位与唯一票码 |
| 6 我的订单 | 状态页签与订单卡，候补位次截止、退票手续费和金额试算、退款结果 |
| 7 组织者管理 | 左侧内联新建演出与多场次多票档编辑，右侧本人活动表，审核进度与历史 |
| 8 管理员审核 | 左侧审核和封禁处理，右侧待办及最近处理；审核意见和驳回原因直接填写 |
| 9 检票工作台 | 窗口状态条、左侧票码身份核验，右侧结果及异常提示，下方本次会话的当日记录 |
| 10 统计导出 | 场次切换，六项统计卡、口径说明、名单导出、缺席说明及各票档售票数据 |

原型的活动、票价、订单与人数属于示例。运行界面全部读取数据库，不把示例的余票、出票结果或统计数字当成实际数据。手机宽度下分栏自动折叠。

是否实名以服务端返回的 `verified` 标记为准，姓名或显示名不代表认证。未实名参与者可浏览演出，详情只提供“先实名认证”入口，不能提交普通订单或预付候补；绕过页面直接请求下单也会被服务端拒绝。认证成功后才能显示提交订单操作。预置演示参与者已绑定虚构实名，新注册账号默认未实名。

检票原型文字写“身份证后四位”，最终需求 REQ-011 要求身份证号核对，因此实现继续核对完整号码，避免降低身份校验。检票记录仅展示当前登录会话中实际核验过的结果，退出即清空；检票员不能查询其他用户、活动或订单。

登录页中的恢复码、角色限定导航、审计与站内消息是已实现业务的必要入口；新增入口使用同一套视觉规范。实名页准确说明本地模拟绑定，不把未实现的真实实名核查或身份证加密存储描述为已实现。
