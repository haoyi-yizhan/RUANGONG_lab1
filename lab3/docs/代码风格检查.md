## 语言和工具

项目主要语言为 **JavaScript**：Node.js 后端使用 `.mjs` ES Modules，浏览器使用 `public/app.js`。HTML 和 CSS 负责页面结构与样式，PowerShell / CMD 仅用于打包与启动。课程列出的 cpplint、Checkstyle 和 Pylint 分别面向其他语言，因此使用适用于 JavaScript 的 ESLint 和 Prettier。

实测环境：Windows x64，Node.js v22.17.0。开发工具版本由 `package-lock.json` 固定：

| 工具 | 版本 | 用途 |
|---|---|---|
| ESLint | 10.15.0 | 推荐静态检查及明确的风格规则 |
| @eslint/js | 10.0.1 | ESLint 推荐规则（精确版本以锁文件为准） |
| @stylistic/eslint-plugin | 5.10.0 | 分号、引号、制表符和行尾空白规则 |
| Prettier | 3.10.1 | 统一代码缩进、换行及排版 |

检查使用项目自定义规则，并未宣称采用 Google 或 Airbnb 的完整风格规范。没有因为首次发现问题而降低规则，也没有添加按行豁免。

## 检查范围和约定

ESLint 检查 `src/`、`scripts/`、`tests/` 的全部 `.mjs`、浏览器 JavaScript 及 ESLint 配置，共 22 个文件；浏览器和 Node.js 分别设置正确的全局变量。Prettier 检查上述文件及 HTML、CSS、配置 JSON，共 26 个文件。

排除依赖、运行数据库、构建副本、证据和 UML 文档，避免把第三方或重复构建内容算进源代码检查范围。具体文件清单和 SHA-256 摘要记录在 `final-summary.json`。

明确规则包括：两空格缩进、分号结尾、单引号（必要时允许双引号或模板字符串）、控制语句必须有大括号、使用 const/let 而不使用 var、适用时使用 const、严格比较（允许明确的 `value == null` 空值检查）、不留未使用变量、不得使用未定义变量、无制表符或行尾空格、LF 换行。Prettier 的排版目标宽度为 100 列，长字符串等不会为满足列宽而改变内容。

## 复现命令

在 `lab3` 目录执行：

```powershell
npm.cmd ci
npm.cmd run lint
npm.cmd run format:check
npm.cmd run style:evidence
npm.cmd test
```

`lint` 使用 `--max-warnings 0`，错误或警告都会导致失败；`format:check` 不修改文件。需要修改代码格式时可以运行 `npm.cmd run lint:fix` 和 `npm.cmd run format`，之后必须重新检查和测试。`style:evidence` 自动保存最终 JSON / 文本记录，任何检查失败返回非零退出码。

参考工具：[ESLint](https://eslint.org/docs/latest/use/)、[ESLint Stylistic](https://eslint.style/)、[Prettier](https://prettier.io/docs/)。
