- 用户授权：完成实验三并讲解，允许分配简单任务给 GPT-6.1 Terra。

- Terra 验收子任务：业务、HTTP 并发、真实进程恢复、性能与行数脚本；父代理提供规约并补充复核发现的回归场景。
- Terra 只读复核子任务：发现停机后时间顺序、已签到变更、纯候补统计问题，由父代理修正。

先确定服务规约，再并行实现 UI 与测试。实际纠错包括：

1. 本机没有 Python，选用已有 Node22 与内置 SQLite，避免运行依赖下载。
2. 初版订单列表逐条查询，性能未达标；改一次 JOIN 后再测达到 100/100，记录见 benchmark.json。
3. 维护先截止退款会错过停机期间的超时递补，改按实际到期顺序回放并补测。
4. 改期遗漏已签到观众，增加撤销旧签到、保留座位及取消全退，补充 UML 与测试。
5. 购票人数错误包含纯候补，改曾出票的不同账号。
6. 注册后前端假登录，改为自动获得真实会话；重置后展示新恢复码。
7. Chrome 启动失败，实际浏览器验证改用 Edge，验证支付退款及手机布局，没有把启动失败算通过。

## 2026-11-11 UI 修订

用户明确要求实验三 UI 与实验二一致。逐张查看十张设计图后，将早期“聚场”侧栏界面改为“校园票务”顶栏和原型页面结构；补充真实候补位次、截止时间、共用退款报价与检票窗口汇总，使用浏览器重新检查页面。检票继续遵守最终需求的完整身份证号核对，示例数据不冒充实际业务结果。

用户随后指出未实名不应购票。修正前端将姓名误当认证依据的问题，统一检查服务端认证标记；详情明确引导实名，并在提交前重新获取用户状态。新增“有显示名但未实名”和“伪造已实名参数”测试，验证普通下单和预付候补都不能绕过服务端身份校验。
