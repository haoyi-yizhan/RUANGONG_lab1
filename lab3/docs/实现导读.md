# 实现导读（AI 辅助技术文档，不是学生实验报告）

## UML 如何变成程序

类图的用户、活动、场次、票档、订单、审核、候补、退款、检票记录和审计分别映射到 SQLite 表；行为由七个服务模块承担。四类用户通过角色字段表达，未创建没有独立行为的空子类。`TicketingSystem` 组合模块，HTTP 层只处理请求、会话和响应，网页只调用 API。

| 实验二职责 | 源文件 | 关键行为 |
|---|---|---|
| M1 账号权限 | auth、security | register/login/verify/resetPassword/setBanned |
| M2 发布审核 | events | createEvent/resubmitEvent/requestChange/review |
| M3 查询 | queries | listEvents/getEvent/listOrders/remaining |
| M4 交易 | trading | createOrder/pay/refund/leaveWaitlist/promoteInternal |
| M5 检票 | operations | openCheckin/checkin/maintain |
| M6 统计导出 | operations | statistics/exportRoster，独立方法共享文件 |
| M7 平台支撑 | support、database | audit/notify/atomic，事务与持久化 |

上表文件均位于 `src/`，扩展名 `.mjs`。组合入口是 `system.mjs`，启动入口是 `server.mjs`。

## 一张票的流转

实名参与者下单，在事务内检查限购和库存，生成待支付订单并占位。三分钟内支付成功时记录资金、分配最小空闲座位、生成随机唯一票码并出票。模拟失败保留待支付，重复成功支付只确认已有结果。超时关闭释放名额。

售罄时预付全款候补，支付与入队一次提交。退票时先算手续费、记退款、修改订单，再按序递补队首，所有步骤在同一事务中。检票后变已签到，结束后变已核销；未到场变已缺席。

余票没有单独保存一个可能不同步的计数：容量减去占位订单就是余票。待支付、已出票、已签到、已核销、已缺席均占位，入场不会错误释放座位。

## 为什么不会超售或退半笔钱

`BEGIN IMMEDIATE` 先获取 SQLite 写权限，再检查库存并落库。同步事务不会在关键步骤中等待网络；并发请求按事务处理顺序执行。有效订单、有效座位、票码、手机、实名、一次支付和一次退款都有唯一约束。

WAL 与 `synchronous=FULL` 保证提交持久化，异常整体回滚。恢复测试实际杀死持有未提交订单事务的子进程，再打开数据库核对不存在半完成订单。启动及每秒维护会处理已提交数据的超时和结束。

恢复维护先按实际支付过期时间回放超时释放及当时可发生的递补，再处理报名截止退款。因此停机跨过两个时间点时，截止前本该获得票的人仍可递补。日志记录实际恢复处理的时间。

## 明确的实现口径

| 规则 | 实现决定 |
|---|---|
| 限购 | 最终澄清为每账号每场次一张；正常退款、退票、超时后可重新买 |
| 退款边界 | 恰好 7 天手续费 40%，恰好 3 天仍可退且 40%，不足 3 天禁止 |
| 金额 | 整数分，手续费按百分比四舍五入到分；退款=实付-手续费 |
| 容量 | 已签到等票仍占位，补全原 REQ-023 有效订单描述的遗漏 |
| 取消未支付 | 未付订单关闭；有效已付和候补订单全退 |
| 已签到变更 | 改期撤销旧签到、保留座位并全退可选；取消则全退 |
| 状态补充 | 增加已签到→已出票（改期）和已签到→已退款（取消），另附补充 UML |
| 统计 | 曾出票的不同账号为购票人数，纯候补不计；当前有效票为出票数 |
| 实名与找回 | 实名为本地模拟；密码找回须提供随机恢复码，重置后轮换 |
| 审计 | API 无编辑删除，数据库触发器拒绝更改；不能抵抗持有数据库文件的系统管理员 |
| 权限 | 参与者本人订单、组织者本人活动及裁剪名单、检票员仅核验，所有 API 隐藏密码哈希 |

## 阅读顺序和风格

先读 system 的组合、database 的模型约束，再读 trading 的状态机和事务，接着读 events 的审核与通知，最后用 tests 对照时间边界及权限。数据层字段 snake_case，API camelCase；mapOrder/eventView 明确转换。

统一使用 ESM、两空格、分号、单引号、驼峰变量、参数化 SQL。check 脚本检查语法、制表符和行尾空格；正式 ESLint 和 Prettier 检查分别通过 `npm run lint` 与 `npm run format:check` 执行，完整记录见 `代码风格检查.md`。DomainError 输出稳定错误码与中文消息，内部 SQL 和堆栈不返回页面。

UI 通过 DOM 文本节点展示用户数据，CSV 防公式注入。密码使用加盐 scrypt，登录令牌哈希入库，Cookie 为 HttpOnly、SameSite=Strict，写请求检查来源与 JSON 类型。

## 实际范围

单实例同步库适合当前课程验收；列表上限 200 活动、500 订单，管理员可精确筛选编号。性能测试是在 1 万订单中查询最近 500 条，不代表返回所有订单。服务只监听 127.0.0.1，默认本地 HTTP；公网部署须另行配置 HTTPS、Secure Cookie 和真实身份支付设施。
