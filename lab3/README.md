# 校园票务 · 活动票务与报名系统

实验三的可运行实现，延续实验一需求与实验二 UML。面向参与者、组织者、检票员、管理员四类角色。采用 JavaScript ES Modules、Node.js 内置 HTTP 与 SQLite，无第三方运行依赖，无 GUI 生成代码。

界面以实验二十张设计原图为基准：白色顶部导航、灰蓝配色，登录及实名为居中卡片，详情与支付为左右分栏，组织者、管理员和检票员使用工作台。具体对应见 `docs/UI对照.md`。首次访问显示登录页，可通过演出入口以访客浏览。

## 快速启动

需要 Node.js **22.13 或更高版本**，推荐 22.x LTS；本机已安装实测的 22.17。

1. 双击本目录的 `启动系统.cmd`，保持窗口开启。
2. 浏览器打开 <http://127.0.0.1:3000>。
3. 用下表账号登录，或自行注册并保存恢复码。
4. 启动窗口按 Ctrl+C 停止。

终端启动方式：在本目录执行 `node src/server.mjs`。首次运行创建 `data/ticketing.sqlite`、四个账号和一场音乐会；重启保留数据。服务只监听本机。支付退款均为站内模拟，实名仅做本地格式校验与唯一绑定。

|---|---|---|---|
| 管理员 | 13800000001 | Admin12345! | 审核、用户、审计、全部活动订单、开检票窗 |
| 检票员 | 13800000002 | Checker123! | 仅票码与身份证号检票 |
| 组织者 | 13800000003 | Organizer123! | 创建、变更、本人活动统计导出 |
| 参与者 | 13800000004 | Participant123! | 已实名，可购票、支付、退款、候补 |

演示参与者的虚构身份证号是 `11010119900101001X`。演示密码属于公开测试数据。新用户须保存注册时的恢复码，重置密码后恢复码轮换且登录会话失效；没有恢复码无法自助重置。预置账号未分发恢复码。

实名认证以账号的认证状态为准，有姓名并不代表已经实名。新账号未实名时只能浏览，购票和预付候补都须先认证。演示参与者预先实名；演示组织者若尚未绑定身份证，首次登录也会引导完成实名认证。

## 操作演示

**购退票：** 参与者登录，查看“校园秋日音乐会”详情与规则，立即报名，在“我的订单”模拟支付，查看座位和唯一票码。演示活动在首次启动十天后开始，立刻退票收取 20% 手续费，100 元票退 80 元。模拟失败保留待支付，可在三分钟内重试。

**候补：** 组织者创建仅一张票的活动，管理员审核通过，两个不同的实名参与者分别购票、候补。第一人退票后队首自动出票。候补预付全款，主动退出或截止未递补时全退。队列顺序来自数据库递增序号。

**审核：** 创建活动时填写多场次、多票档。时间满足“上线 ≤ 起售 < 截止 ≤ 开始 < 结束”。管理员通过或填写原因驳回，组织者可修改被驳回申请再次提交。上线后不可更改票价、容量或增加票档。

**变更：** 组织者申请改期或取消，审核期间继续售票。改期通过后原有已出票订单获得全额退款权，已签到订单撤销旧签到并保留座位。取消通过后关闭待支付订单，有效已付及候补订单全额退款并通知。

**检票：** 管理员在开演前三小时内，选择场次开启检票窗。以检票员登录，输入票码和实名身份证号。重复、伪造、已退款票及身份不匹配均拒绝。演出结束后台把已签到转已核销、未到场转已缺席。自动测试通过可控时钟验证时间场景，不必手动改电脑时间。

**统计：** 组织者查看本人场次统计，导出姓名、联系方式、座位号 CSV，不含身份证号，导出留审计。上座率 = 到场 / 当前有效出票；无出票时不适用。购票人数统计曾出票的不同用户，纯候补不计。

## 构建与验证

在本目录运行，无需 `npm install`。若 PowerShell 限制 npm.ps1，可使用 `npm.cmd` 或直接执行脚本。

| 目的 | 命令 |
|---|---|
| 自动验收 | `npm test` |
| 保存测试证据 | `npm run test:evidence` |
| 语法与基础空白风格检查 | `npm run check` |
| 代码规模 | `npm run count` |
| 1 万订单、20 并发、100 查询 | `npm run benchmark` |
| 实际浏览器操作及截图 | `npm run test:browser` |
| 校验并构建独立运行目录 | `npm run build` |

JavaScript 由 Node.js 直接执行，构建进行语法检查、复制运行文件，输出到 `dist/ticketing-时间戳/`，其中执行 `node src/server.mjs` 即可运行。每次保留旧构建。SQLite 的 ExperimentalWarning 是 Node 22 内置 API 提示，不是失败。基础风格检查不等同于完整 ESLint 分析。

浏览器测试隐藏运行本机 Edge/Chrome，可用 `CHROME_PATH` 指定浏览器，截图在 `artifacts/`；正式运行证据在 `evidence/`。测试采用独立内存库或临时库，不影响正常运行数据。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/package.ps1 -StudentId 你的学号 -StudentName 你的姓名 -ReportPath 你的报告完整路径.pdf
```
